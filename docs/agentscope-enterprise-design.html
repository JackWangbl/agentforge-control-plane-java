1. 系统定位

AgentForge 控制面是企业里的 Agent 管理平面，不是一个对话玩具。它要解决四件事：谁能用哪个 Agent、这个 Agent 能调哪些工具和文档、一次运行留下什么痕迹、换一个人之后还能不能把别人的数据翻出来。

做不做

2. 架构

2.1 物理部署

本机开发时就是三块：控制面进程、远程或本地 MySQL、可选的 Milvus。模型都走 HTTP，不内嵌推理。

浏览器只打控制面。Milvus、模型密钥、试用 cookie 都不下发到前端。试用访问 /api/models 得到 403，避免把密钥列表暴露出去。

2.2 逻辑分层

请求进入后的固定顺序：解析 Bearer（或试用 token）→ 可选 X-Tenant-Id 切换租户 → 权限注解 → Controller → 领域服务。需要模型时才进 AgentScopeRuntime。工具回调不走第二次 HTTP，而是 AgentScope 在进程内调 DelegatingTool，再进 ToolRuntime。

3. 领域模型

所有带属主的业务对象继承 TenantOwnedEntity：tenant_id 必填，默认 1；owner_id 可空。时间列在 TimestampedEntity：id、created_at、updated_at（UTC）。Trace 例外，它只有 started_at。

3.1 身份聚合

实体关键字段规则
Tenantslug、name、description平台管理员可切到其他租户；普通用户不能
Userusername 全局唯一、password_hash、role_id、enabledguest 是试用共用账号，不能当长期记忆主键
Roletenant_id、permissions 字符串列表* 和 platform:admin 全放行；:write 隐含对应 :read；eval:run 兼评测读写
AuthTokentoken、user_id、expires_at、trial_key试用 token 过期文案是「试用已结束」。cookie af_trial 存 trial_key，7 天，HttpOnly

subject_key 不是单独一张表，是会话和记忆上的身份串：已登录 user:{用户id}，试用 trial:{af_trial}。平台管理员切租户后，看到的是自己在那个租户下的记忆，不是该租户其他人的记忆。

Tracetrace_id、session_id、spans JSON、input/output tokens、duration_ms步骤 title 为「调用工具 search_documents」，没有名为 RAG 的节点

3.6 质量聚合

3.7 资源可见性（和知识库不同）

Agent、模型、Skill、MCP、会话列表等走 ResourceAccessService：同租户有对应读权限就能看见彼此的配置。知识库和记忆更严：知识库默认私有，记忆永远只看自己。不要把这两套规则混为一谈。

4. 核心流程

4.1 登录与试用

AuthService.trialDecision：cookie 对不上库 → new；过期时间在未来 → resume；已到期 → expired，不再发新试用。清 localStorage 无效，因为时钟在 HttpOnly cookie 和 auth_tokens 行上。

4.2 一轮调试台对话（主路径）

  1. POST /api/playground/run，权限 session:write 或 agent:write。
  2. 取出 Agent，用 Agent.model_name 解析 chat 模型。若绑了 HTTP Agent，改走外部平台。
  3. 按 session_id 取 Conversation：跨租户拒绝；跨 Agent 拒绝（实验分流时换新 session）。subject_key 对不上则拒绝「这个会话属于其他人」。
  4. MemoryService.shortTermHistory 取本会话窗口，再追加本轮用户消息。
  5. PlaygroundService.generate → ExecutionContext.runScoped → AgentScopeRuntime.generate。
  6. 无密钥：返回 preview，可选执行 get_current_time。有密钥：组系统提示词、Toolkit、ReActAgent.call，最多 4 轮（浏览器/OpenCLI 为 8）。
  7. 工具执行时 CurrentUserHolder.call(caller, ...)，search_documents / remember / forget 都能看见登录人。
  8. 失败则把 working、pending_tools 写入工作区检查点，前端可 resume。
  9. 成功则 finalizeTurn 写 ChatMessage、Conversation（补 subject_key）、Trace、工作区会话文件。
  10. mode=ready 时 MemorySummarizer.summarize 再调一次 chat/completions，把稳定事实写入 memory_items。失败只打日志。

4.3 知识库入库与检索

入库：上传（txt/md/html/csv/docx/pdf，16MB）→ 落盘 rag-files/tenants/{tenant}/knowledge/{id}/ → 清洗 → 按形态选策略（qa / article / table_row / heading / paragraph / sentence，否则 recursive）→ 子块约中文 450 字重叠 60 → 调 embedding → 写入 Milvus。子块字段 content 用于向量和 BM25，context 是所在章节，最长 2000 字，交给模型。

检索：问题 embedding → 当前可见且已绑定的每个库做 AnnSearchReq（稠密 COSINE + 稀疏 BM25）→ RRFRanker(60) → 可选 rerank → 阈值 → 合并最多 10 条。返回「【n】库名 / 文件名 / 标题 + context」。

4.4 记忆

短期：同会话 chat_messages，换会话清零。长期：总结器只收偏好、资料、决定、更正；已有相同正文字面不重复 add；用户否定则 delete。页面只改正、置顶、删除。试用按浏览器凭证分开，登录后不自动合并试用记忆。

4.5 对外调用与评测

POST /api/agents/{id}/invoke 与调试台共用 BoundAgentRuntime：有登录人则走短期窗口并写会话、再总结记忆。评测每题新 session，走 run()，也会带短期窗口，但新会话通常只有当前一句；评测不调用总结器。

5.1 身份穿过工具线程

AgentScope 的工具不在 HTTP 线程上跑。如果只靠 ThreadLocal，search_documents 会看到空用户，返回「当前没有你可以检索的文档」。做法：generate 入口 CurrentUser caller = CurrentUserHolder.get()，buildToolkit 和 runPending 都用 CurrentUserHolder.call(caller, supplier) 包一层执行。

5.2 检查点

每一步 flush 写 workspaces/.../sessions/{session}.ckpt.json：working、pending_tools、done_tool_ids、next=llm|tool。失败后续跑不重新截短期窗口，直接恢复 working。

5.3 数据迁移原则

不改已有列含义，只 ADD TABLE/COLUMN。最近补过：auth_tokens.trial_key、model_configs.purpose、knowledge_*、visitor_days、memory_items、conversations.subject_key。

6. AgentScope 学习教程

这一节只讲本项目真正用到的 AgentScope Java 2.0.3，不讲仓库里没有接的 Python 生态或未引入的扩展。学完应能看懂 AgentScopeRuntime，并能加一个企业工具。

6.1 它在企业里干什么

AgentScope 提供「模型 ↔ 工具」循环，不提供租户、权限、知识库 ACL。企业把循环嵌进控制面：

AgentScope 对象控制面谁来填
ReActAgent.name / sysPromptAgent.name，ToolRuntime.buildSystemPrompt（人设+Skill+工具说明+知识库提示+长期记忆）
OpenAIChatModelModelConfig 的 model_id、base_url、密钥、temperature
ToolkitToolRuntime.agentTools 转成 DelegatingTool，执行仍回 executeTool
List<Msg>短期记忆窗口 + 本轮用户消息，映射成 UserMessage / AssistantMessage / ToolResultMessage
RuntimeContext当前写死 userId="playground"，sessionId 用调试会话。真正身份在 CurrentUserHolder，不在这个对象里
不要以为 RuntimeContext.userId 就是登录用户。本项目的鉴权在 CurrentUserHolder。改企业功能时跟控制面身份，不要去改 AgentScope 的 userId 当 ACL。

6.2 ReAct 循环（必须理解）

  1. 把系统提示词和历史消息交给模型。
  2. 模型要么直接输出文本结束，要么输出 tool_call。
  3. AgentScope 按 Toolkit 找到工具并执行，把结果作为 tool 消息回灌。
  4. 再调模型。重复直到没有工具调用，或达到 maxIters。

本项目 maxIters：普通 4，名字以 browser_ 或 opencli_ 开头则 8。打开了 enablePendingToolRecovery(true)：工具调用中断时可以留下 pending，用 /api/playground/resume 续跑。

ReActAgent react = ReActAgent.builder()
    .name(agent.getName())
    .sysPrompt(tools.buildSystemPrompt(agent))
    .model(chatModel)
    .toolkit(toolkit)
    .maxIters(maxIters)
    .enablePendingToolRecovery(true)
    .generateOptions(GenerateOptions.builder().temperature(model.getTemperature()).build())
    .build();
Msg result = react.call(msgs, RuntimeContext.builder()
        .userId("playground")
        .sessionId(sessionId)
        .build())
    .block(Duration.ofMinutes(5));

6.3 消息类型

本项目 history.roleAgentScope 类何时出现
userUserMessage人说话、短期窗口里的历史用户句
assistantAssistantMessage，可带 ToolUseBlock[]模型回复或上一轮未完成的 tool_calls

toMsgs 负责这层转换。新代码如果往 history 里塞了别的 role，模型看不到。

6.4 模型适配

用的是 io.agentscope.extensions.model.openai.OpenAIChatModel，不是 DashScope 扩展（依赖里有，运行时没走）。DeepSeek、智谱、Kimi 只要提供 OpenAI 兼容的 /v1/chat/completions 即可。base_url 去尾斜杠；空则按 provider 猜 DashScope 或 OpenAI 官方。

向量和重排序不走 AgentScope。embedding 是控制面 EmbeddingClient 自己 POST /embeddings。rerank 是 HttpRerankClient POST /rerank。把 chat 模型指到 embeddings 地址会 400。

6.5 工具怎么注册

AgentScope 的 Toolkit 需要带 JSON Schema 的工具。本项目用 ToolSpec(name, description, parameters)，parameters 是标准 JSON Schema。注册时包成 DelegatingTool：模型只看到名字和参数，执行闭包里再鉴权、恢复身份、调 executeTool、写一条 span「调用工具 {name}」。

当前会进 Toolkit 的工具：

  • Agent 绑定的 MCP 工具（含内置时间、计算、浏览器）
  • 沙箱 sandbox_*
  • 有就绪文档时的 search_documents
  • 长期记忆 remember / forget / list_memories（HTTP Agent 除外）
  • tool_flows 展开的 flow_*

新增企业工具的标准步骤：

  1. 在 ToolRuntime.agentTools 里 new ToolSpec(...)，参数用 ToolSpec.objectSchema。
  2. 在 agentAllowsTool 里声明何时允许。
  3. 在 executeTool 里实现。身份用 CurrentUserHolder.get()，不要从模型参数里收 user_id。
  4. 需要时在 buildSystemPrompt 加一句「什么情况下必须先调这个工具」。
  5. 用调试台看执行链路是否出现「调用工具 你的名字」。

6.6 系统提示词怎么叠

顺序固定：人设 → Skill 全文 → MCP/沙箱工具名单 → 编排提示 → 知识库「必须先 search_documents」→ 长期记忆清单。HTTP Agent 只用 Agent 自己的 system_prompt，不加后面这些。

6.7 超时、预览、失败

  • 没有密钥：不创建 ReActAgent，返回 preview 文本。
  • call 最多阻塞 5 分钟。
  • 异常：密钥从错误串里打码，检查点 status=failed，回复 mode=error，并附一段预览，避免前端空白。

6.8 学习顺序（建议按这个读代码）

  1. ToolSpec、ChatReply：看输入输出长什么样。
  2. AgentScopeRuntime.toMsgs、buildToolkit、buildModel：看 AgentScope 边界。
  3. generate 主循环和 flush：看检查点。
  4. ToolRuntime.executeTool 和 CurrentUserHolder.call：看企业身份。
  5. KnowledgeSearchService.searchForAgent、MemorySummarizer：看知识与记忆如何挂在循环外。

7. 企业实战教程

下面按这个仓库能点出来的界面写。账号种子：linmo/admin123（平台管理员）、developer/dev123、auditor/audit123、demo/demo123。试用用户名 guest，不能登录。

7.1 启动

  1. .env 里 DATABASE_URL 必须是 mysql+pymysql:// 或 jdbc:mysql://。占位文字会导致启动失败。
  2. JDK 用 21+（本机常用 openjdk-26）。mvn spring-boot:run，打开 http://127.0.0.1:8080 。
  3. 需要知识库时再起 Milvus（本机常见 127.0.0.1:19530）。没有默认向量连接时，先到「向量数据库」登记并设为默认。

7.2 配三种模型

  1. 模型配置 → 新建，用途选「对话」。填 OpenAI 兼容地址、模型 id、密钥。这是 Agent 的 model_name。
  2. 再新建用途「向量」。智谱用 embedding-3 或 embedding-2。不要把 glm-4-flash 填成向量。
  3. 再新建用途「重排序」。智谱模型 id 必须是 rerank。不配也可以，检索走 RRF 截断。
  4. 试用账号看不到这一页。密钥不要写进 README。

7.3 建一个企业助手

  1. Agent 管理 → 新建。名称、说明、绑定刚建的对话模型。system_prompt 写职责，不要写制度全文。
  2. 需要流程约束就建 Skill，把条款写进 instruction，再勾到 Agent。
  3. 需要实时能力就绑 MCP 或沙箱。浏览器和本地时间是内置 MCP。
  4. 保存。调试台选这个 Agent。不要指望页面上再选一次模型。

7.4 知识库：私有制度 vs 全员制度

  1. 知识库 → 新建。选向量模型。可见性先 private。
  2. 上传 PDF/Markdown。等状态 ready，看自动策略和理由。需要可改策略后重建。
  3. 回到 Agent，勾选这个库。
  4. 用属主在调试台问文档里的数字。执行链路应出现「调用工具 search_documents」，再出现「调用模型」。回答应依据章节，而不是模型常识。
  5. 用另一个账号打开同一 Agent 问同一句。应得到「当前没有你可以检索的文档」或与该库无关的回答，且响应里没有库名。
  6. 全员制度：把库改成租户公开，或把对方加成 viewer。对方应能检索，仍不能上传（viewer）。

7.5 记忆

  1. 属主在调试台说稳定偏好，例如「以后回答先给结论，用中文」。
  2. 等回复结束后打开「记忆」。应出现自动总结，来源为自动总结。
  3. 新开一个会话问「你准备怎么回答我」。应沿用长期记忆，而不是上一会话的闲聊全文。
  4. 另一个账号的记忆页必须是空的或只有他自己的。
  5. 试用换浏览器，记忆不能串。登录后不自动带上试用期间的记忆。
  6. 改错了就在记忆页改正或删除。不要在页面上手工「添加一条当主数据」——主数据来自对话总结。

7.6 评测和 A/B

  1. 数据测试里建数据集，每行一个 input 和 expected。
  2. 选中 Agent 跑评测。每题新 session。看 actual、耗时、Trace。
  3. 要对比两个 system_prompt 或两个 Agent：建实验，加两个 variant，启动后 status=running，调试台选实验再聊。只有进行中的实验会改 agent_id。

7.7 对外接口

其他系统调用 POST /api/agents/{id}/invoke，body 为 message 和可选 session_id。带上登录 Bearer。同一 session_id 会续短期记忆。这是本平台 Agent 的出口。登记别人的 HTTP Agent 是反向：我们当客户端。

curl -s http://127.0.0.1:8080/api/agents/10/invoke \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"message":"北京GDP是多少","session_id":"biz_001"}'

7.8 权限怎么配给部门

  • 开发：agent/mcp/skill/knowledge 读写 + session 写 + 模型读。
  • 业务试用：除 model:read/write 外的产品权限。对应种子角色「试用访客」。
  • 审计：session:read、trace:read、eval:read，不要模型写、不要知识库写。
  • 租户管理员：能进向量库设置，不能自动变成别人私有库的检索者。

7.9 上线检查

  • 改掉种子密码。不要提交 .env。
  • 确认 DATABASE_URL 不是占位符。
  • 对话、向量、重排序三种模型分开测通。
  • 用两个账号验证知识库交集和记忆隔离。
  • 看一条真实 Trace：调用模型 → 调用工具 search_documents → 再调用模型。
  • 静态资源改完后提高 app.js?v=。
