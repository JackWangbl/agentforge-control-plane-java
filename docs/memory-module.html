记忆模块设计方案

待审查AgentForge 控制面 · 2026-09-23 · 批准后再写代码

给每个登录用户一份只属于自己的记忆。短期记忆让同一次对话接得上上文。长期记忆让换一个会话之后，仍然记得这个人明确留下的事实。隔离键是租户加上这个人，管理员不能借身份看到别人的记忆。

1. 要补上的能力

调试台现在会把同一个会话里已经存下的 chat_messages 再送给模型，所以一轮对话里能接着上文说。换一个会话、换一天再来，这些内容不会被当成「这个人的记忆」带回去。

另外有三处和记忆相关的缺口：

  1. 评测和一部分接口调用只把当前这一句发给模型，同一次会话的上文也不带。
  2. 模型运行时写死的用户标识是 playground，不是登录用户。知识库检索已经改成携带真实登录身份，记忆要走同一条路。
  3. 试用访客在库里是同一个 guest 用户。如果按用户 id 记长期记忆，所有试用浏览器会共用一份。

知识库继续负责文档。记忆负责这个人自己的事实。两者不共用表，也不共用检索。

2. 参照

做法本方案采纳的部分
ChatGPT Memory用户能看见、修改、删除自己的长期记忆。模型只在用户明确要求记住或忘掉时写入
Mem0长期记忆是短事实，按用户隔离，有添加、检索、删除
AgentScope 的对话 Memory短期记忆就是当前会话的消息列表，有长度窗口
Dify 会话变量与知识库会话上下文、个人事实、文档知识库分成三种东西

本版不采纳：每轮对话自动抽取摘要、向量检索记忆、把记忆分享给其他用户、管理员查看全员记忆。

3. 两层怎么分

当前这一轮用户消息
        │
        ├─ 短期记忆：本会话最近若干轮（chat_messages）
        │
        └─ 长期记忆：这个人在这个租户下的事实（memory_items）
                │
                ▼
        系统提示词里的一小段 + 模型可调用的记忆工具
                │
                ▼
        现有 ReAct 对话（知识库、MCP、技能保持原样）

3.1 短期记忆

不新建表。来源就是现有的 chat_messages。范围是一次会话。

项规则
何时注入同一次会话的后续轮次。新会话不带上一会话的原文
窗口最近 20 条，并且总字数不超过约 6000。先碰到的限制生效。本轮用户消息始终保留
谁能读到这条会话的主人。已登录用户还要 owner_id 等于自己，并且租户一致
界面仍在「会话查询」里看原文。不另做短期记忆编辑页
续跑失败检查点继续用检查点里的 working 历史，不再截一刀

调试台、绑定 Agent 的调用、评测，生成前都走这一个窗口函数。现在评测走的是只含当前一句的入口，本方案把它改过来。

3.2 长期记忆

一条长期记忆是一句稳定事实：偏好、称呼、做过的决定、用户要求更正的内容。换会话、换一天仍然注入。

项规则
归属租户 + 这个人。这个人在该租户里的各个 Agent 都能读到
单条长度最多 500 字
条数每个身份在每个租户最多 200 条未删除记录
注入置顶的在前，其余按更新时间。最多 12 条，合计约 1500 字，写进系统提示词
写入记忆页手工添加；或用户在对话里明确说「记住」「忘掉」时，由工具写入
删除从列表和后续注入中消失。库内软删除，界面不提供回收站
请确认：长期记忆默认不按 Agent 拆开。表上预留可空的 agent_id，第一版界面不展示这个字段，值保持为空。若审查时希望「个人助手」和「客服助手」各记各的，把该字段改成按 Agent 隔离即可，不必换表。

4. 隔离

身份键 subject_key：

谁键原因
已登录用户user:{用户 id}稳定，不随显示名变化
试用访客trial:{af_trial 凭证}试用账号都是 guest，用户 id 相同，不能拿来分开两个人

每一条查询同时带上当前 tenant_id 和 subject_key。平台管理员用租户切换器换到另一个租户时，看到的是自己在那个租户下的记忆，不是该租户其他人的记忆。直接用 id 访问别人的记录，返回不存在。

记忆不跨租户携带。同一个人在默认租户和演示租户各有一份。

短期记忆沿用会话。会话创建时写入同一个 subject_key。读取历史时，会话上的键必须等于当前身份，租户也必须一致。旧会话这条键为空时：已登录用户按 owner_id 匹配；试用用户不读取空键历史，避免串到共用的 guest 会话上。

试用凭证和访问次数用的是同一个 af_trial cookie。登录之后改按用户 id 记，试用期间写下的长期记忆不自动并进登录账号。

5. 数据

SchemaMigrator 增加 memory_items。已有表只加列，不改对话和知识库的表结构，除了会话上补一列身份键。

5.1 memory_items

列说明
id主键
tenant_id租户
subject_keyuser:{id} 或 trial:{凭证}，最长 120
agent_id可空。空表示该用户在该租户的全部 Agent 可用
content事实正文，最长 500 字
kindpreference、profile、decision、correction。界面显示为偏好、资料、决定、更正
sourceuser 页面写入，agent 对话工具写入
pinned置顶后优先注入
session_id可空。对话里记住时记下当时的会话，方便对账
created_at / updated_at时间
deleted_at可空。有值则列表和注入都跳过

索引：(tenant_id, subject_key, deleted_at)。正文留在 MySQL。一个人几十到几百条，按时间和置顶取值即可。以后条数上来，再接到现有 Milvus，本版不做向量。

5.2 conversations 增加一列

列说明
subject_key可空，最长 120。新会话在创建时写入。用于短期历史的主人校验

6. 生成回复时怎么用

挂在现有两个点上，不新开一条对话链路。

  1. 系统提示词。ToolRuntime.buildSystemPrompt 在技能、工具说明、知识库提示之后，追加一段「关于当前用户的记忆」。身份来自 CurrentUserHolder，工具线程上已经能拿到登录用户。
  2. 本轮消息列表。调试台、绑定调用、评测在调用 generate 之前，把短期窗口放在本轮用户消息前面。

注入文本的形状：

关于当前用户的记忆（仅供回答时参考，不要主动复述整份清单）：
- [偏好] 回答使用中文，结论放在前面
- [资料] 称呼用林默
用户要求记住、更正或忘掉时，调用 remember 或 forget。

记忆服务出错时，本轮省略这段，对话继续。日志记一条失败原因，不把数据库错误返回给用户。

6.1 工具

在现有工具列表里增加三个，和 search_documents 一样按当前身份执行。

工具作用
remember写入一条长期记忆。参数：正文、类型。超过 500 字或超过 200 条时返回失败原因
forget按正文关键词软删除当前身份下匹配的记忆。没有匹配时说明没找到，不删别人的
list_memories按关键词列出当前身份的记忆，给模型在提示词片段之外再查一条。只返回自己的

系统提示词约束模型：只有用户明确说记住、更正或忘掉时才调用 remember 和 forget。闲聊、问答、知识库检索的结果不写入长期记忆。

请确认：第一版不做「每轮结束自动总结并写入」。自动写入容易把闲聊变成事实。需要的话作为下一版，并且写入前在界面里给用户看一条待确认。

7. 界面和接口

侧栏增加「记忆」，试用用户可见。模型配置页对试用保持隐藏，这一点不变。

页面只有自己的长期记忆：

  • 列表：正文、类型、来源（我添加 / 对话记住）、更新时间、是否置顶。
  • 操作：新增、编辑、置顶、删除。
  • 空状态说明：在这里写下希望 Agent 一直记得的事实，或在对话里说「记住……」。
  • 没有「查看他人」、没有租户全量、没有按用户筛选。

接口都要求已登录或处于试用中。服务层再次按租户和 subject_key 过滤。

接口行为
GET /api/memories当前身份的未删除记忆，置顶在前
POST /api/memories新增。来源记为 user
PATCH /api/memories/{id}改正文、类型或置顶。不是自己的 id 返回不存在
DELETE /api/memories/{id}软删除

不新增「管理员可读全部记忆」的权限。进这个页面不需要 tenant:admin。

8. 和现有对象的关系

现有对象本方案中的位置
会话消息 chat_messages短期记忆的原文。增加读取窗口和主人校验
会话 conversations补 subject_key。标题、状态、统计不变
知识库不改。文档检索仍然按成员和可见性取交集
访问次数 visitor_days不改。那是概览计数，不是记忆
工作区检查点只用于失败后续跑。不作为跨会话记忆

9. 实现时会动到的位置

批准后按这些点改，避免另起一套运行时。

  • SchemaMigrator：建 memory_items，给 conversations 加 subject_key。
  • 新建记忆服务：身份键、窗口、增删改查、注入文本。
  • ToolRuntime.buildSystemPrompt 和工具注册：挂上长期记忆片段和三个工具。
  • PlaygroundController、BoundAgentRuntime、EvalService：生成前套上短期窗口。
  • 会话创建：写入 subject_key。
  • 前端：侧栏「记忆」页，以及 app.js 的缓存版本号。

10. 验收

  1. 用户 A 在记忆页新增「称呼用林默」。用户 B 的列表里没有这条，用 id 访问得到不存在。
  2. A 换一个新会话问「你怎么称呼我」，回答使用这条长期记忆。B 问同样的问题，不会出现林默。
  3. A 在默认租户写下的记忆，切到演示租户后看不到。切回来仍然在。
  4. 两个试用浏览器各记一条，互相看不到。试用结束后登录，不会自动带上试用期间的记忆。
  5. 同一会话里第二轮能接上第一轮的上文。超过窗口的更早轮次不再整段送入。
  6. 对话里说「记住我喜欢先看结论」，记忆页出现来源为「对话记住」的一条。说「忘掉」之后，下一轮不再注入。
  7. 闲聊一轮之后，记忆条数不增加。
  8. 记忆库暂时不可用时，对话仍能完成，只是这一轮没有记忆片段。
  9. 平台管理员打开记忆页，只能看到自己的记录。
